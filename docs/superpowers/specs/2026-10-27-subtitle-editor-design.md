# 字幕編輯器（對軸調軸）設計

日期：2026-10-27　狀態：待使用者審閱

## 目的

使用者手上有自己的影片，想在瀏覽器裡一邊播影片、一邊看字幕疊在畫面上、一邊改字與對軸，改完直接存回 `content/videos/<ID>.md`，並能匯出 ASS／SRT。

成功標準：
- 改完存檔後 `npm run validate:content` 仍通過，md 裡被改動以外的行一個字都不變。
- 編輯器預覽、匯出的 ASS、網站「影片上的字幕」三者的標點與上色規則一致（同一份程式）。
- 雙擊 `edit_subs.bat` 就能開始用。

## 範圍

第一版做：載入 md＋本機影片、字幕疊層預覽、字幕列表、時間軸方塊、對軸調軸、拆列／合併、復原／重做、存回 md、匯出 ASS／SRT、存檔前驗證。

第一版不做：音訊波形、多人同時編輯、在編輯器裡改 `colors:` 色設定、新增或刪除整支影片的 md。

## 架構

不是網站的一部分，不會被部署到 GitHub Pages。

```
edit_subs.bat                      雙擊啟動：node tools/subtitle-editor/server.mjs，開瀏覽器
tools/subtitle-editor/
  server.mjs                       本機小伺服器（只綁 127.0.0.1，port 3300）
  md.mjs                           md 解析與寫回（保留所有非字幕行與各行原本的換行）
  export-ass.mjs                   ASS／SRT 產生（由 scratchpad 的 export-subs.mjs 整理而來）
  index.html                       介面（單檔，內含 CSS 與 JS，不用打包）
  check.mjs                        檢查腳本（npm run editor:check）
```

- 伺服器直接 import `src/lib/subtitle.ts`（Node 24 可直接載入 .ts），並用 `node:module` 的 `stripTypeScriptTypes` 把它轉成 JS，以 `/lib/subtitle.js` 提供給瀏覽器。標點（`plainSubtitle`）、補引號（`balanceQuotes`）、上色（`colorizeSubtitle`）、停留時間（`buildSubtitleRows`）只有這一份。
- 影片不經過伺服器：瀏覽器用 `<input type="file">` 選檔，以 object URL 播放。

### API（都只接受 11 碼 YouTube ID，不接受路徑）

| 路由 | 作用 |
|---|---|
| `GET /api/videos` | 列出 `content/videos/*.md` 的 ID、標題 |
| `GET /api/video/:id` | 回傳解析後的列（起、訖、字）、`colors`、檔案雜湊 |
| `PUT /api/video/:id` | 收整份列資料，驗證後寫回 md（原子寫入）；雜湊對不上就拒絕 |
| `GET /api/video/:id/ass?full=1`、`/srt` | 匯出檔下載（`full=1` 是主色＋輔色外框的原案配色） |
| `GET /lib/subtitle.js` | 共用的字幕邏輯 |

## md 寫回規則

- 逐行處理：符合字幕行格式 `[起]` 或 `[起-訖] 字` 的才可能被改；檔頭、`colors:`、標題、空行、註解原樣保留，每行保留原本的 CRLF 或 LF。
- 沒被改過的字幕行原樣輸出；被改過的行才重新格式化：一律 `[起-訖] 字`，時間 100 分鐘內寫 `mm:ss.d`，超過寫 `hh:mm:ss.d`，精度 0.1 秒。
- 拆列、合併會新增或刪除字幕行；其餘行的相對位置不動。
- 載入時記錄檔案內容雜湊，寫回前比對，磁碟上的檔案被別處改過就拒絕覆蓋並提示重新載入。
- 用暫存檔再改名的方式寫入，避免寫到一半損毀。還原靠 git。

## 驗證（存檔前，錯誤擋存檔、警告只標示）

錯誤（紅）：
- 起點時間倒退（下一列起點早於上一列起點）。
- 訖不晚於起。
- 訖晚於下一列起點。
- 字為空。

警告（黃）：
- 一列超過 12 字（去標點後算，同 retime 的 `MAX`）。
- 停留太短（少於字數所需的最低讀取時間）。

規則與 `scripts/validate-content.mjs` 一致；存檔後伺服器再跑一次同一套檢查，結果與 validate:content 相同。

## 介面

- 左：影片（含播放控制、倍速）＋字幕疊層（白字黑外框、名字主色／輔色外框、熟肉標點、無底條，與 ASS 輸出同觀感）。
- 右：字幕列表，播放到哪列就高亮並捲到該列；點一列跳到該列起點；行內可直接改字，起訖可輸入數字。
- 下：時間軸，每列一個方塊，可拖曳整塊、拖兩端改起訖，可縮放；紅黃標示對應驗證結果。
- 上方工具列：載入 ID／影片、存檔、匯出、復原、重做、整體平移輸入框。

### 對軸調軸操作

| 操作 | 說明 |
|---|---|
| 整體平移 | 對全部、選取的列、或「從這列往後」加減秒數 |
| 微調 | 起或訖 ±0.1 秒（快捷鍵）；「設成目前播放位置」 |
| 打點 | 播放中按鍵，把目前列的起點或訖點設成現在的時間 |
| 拆列 | 在目前播放位置把一列切成兩列（字從游標處切） |
| 合併 | 把相鄰兩列併成一列（起取前者、訖取後者） |
| 復原／重做 | 每個編輯動作一步，至少保留 100 步 |

## 錯誤處理

- 影片格式瀏覽器播不了：提示換 mp4／webm，字幕編輯本身仍可用（時間軸以字幕最後一列為長度）。
- 伺服器 port 被占用：提示並換用下一個 port。
- 存檔被拒（驗證錯誤、雜湊不符、寫入失敗）：不改磁碟，畫面顯示原因，未存的編輯保留在頁面裡。
- 頁面關閉前有未存的編輯：用瀏覽器的離開確認提醒。

## 測試

`check.mjs`（Node，不用測試框架，壞了就丟錯、結束碼非 0）：
- 時間格式轉換（含超過 100 分鐘）來回一致。
- md 往返：不改任何東西讀入再寫出，與原檔逐位元組相同（含混合 CRLF／LF）。
- 只改一列後寫出，與原檔只差那一行。
- 平移、拆列、合併、復原重做的結果。
- 驗證規則：倒退、訖不晚於起、訖晚於下一列起點、超過 12 字。
- 匯出的 ASS／SRT 與既有腳本輸出一致（標點、上色、時間）。
- 用 `okctzi0u47Y.md`（784 列）跑一次往返與匯出。

介面部分用瀏覽器實際載入檢查：載入、播放同步高亮、拖曳時間軸、存檔，並依專案習慣在宣告完成前跑視覺對齊的量測。

## 已知取捨

- 需要先有 node 才能用（專案本來就需要）。
- 時間精度只有 0.1 秒（md 格式本來就只有一位小數）。
- 一小時以上的影片放時間軸方塊要做虛擬化（只畫可見範圍），否則 800 多個方塊會拖慢拖曳。
